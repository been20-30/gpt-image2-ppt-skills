# gpt-image-2 幻灯片高保真可编辑 PPTX 设计

- 日期：2026-07-11
- 状态：已确认，待用户复核书面规格
- 适用仓库：`gpt-image2-ppt-skills`

## 1. 背景

当前系统让 gpt-image-2 生成包含背景、文字、图形和装饰的完整幻灯片 PNG，再将 PNG 铺满 PowerPoint 页面。该模式能最大程度保留图片模型对字体尺度、字形气质、留白、光影、构图和视觉节奏的整体设计能力，但标题、正文、数字和图表标签无法在 PowerPoint 中直接编辑。

本设计不把 gpt-image-2 降级为“无文字背景生成器”。完整的、包含文字的幻灯片仍是视觉母版。系统在生成结束后，把视觉母版反向重建为分层 PPTX：语义文字转换为 PowerPoint 原生文本，复杂视觉保留原始像素或独立重建为素材，简单结构在质量允许时转换为原生形状。

## 2. 产品定义

“可编辑”在本项目中的首要含义是：

1. 标题、正文、数字、日期、页脚、图例、坐标轴标签和图表注释可以在 PowerPoint 中直接双击修改。
2. Logo、照片、插画、3D 物体和复杂视觉可以作为独立图片对象选择、隐藏、缩放、替换和调整层级。
3. 简单卡片、色块、线条和几何图形可以逐步转换为 PowerPoint 原生形状，但不作为第一阶段的硬性条件。
4. 初次打开 PPTX 时，视觉效果应尽量接近 gpt-image-2 的完整母版。

复杂插画的每一个像素不要求转换为 PowerPoint shape。“语义内容可编辑、复杂视觉可独立替换”是默认交付边界。

## 3. 目标

### 3.1 必须实现

- 保留 gpt-image-2 完整页面生成能力，不改变现有视觉母版流程。
- 使用 `slides_plan.md` 和生成元数据中的确定文案重建原生文本，OCR 主要负责位置、行结构和视觉属性检测。
- 擦除视觉母版中的旧文字，避免原生文字修改后露出背景残影。
- 支持重叠视觉素材的原像素直抠、局部遮挡补全和 AI 分离重建。
- 默认选择最保真的原像素直抠，仅在质量不合格或用户明确进入设计模式时使用 AI 分离重建。
- 通过 PowerPoint、Keynote 或 LibreOffice 的真实渲染结果做闭环质检。
- 保留现有整页图片 PPTX 模式，新增可编辑模式，不破坏已有用户工作流。

### 3.2 非目标

- 不承诺从单张 PNG 恢复生成前不存在的真实设计源文件或原始图层。
- 不承诺 AI 生成字形能找到像素完全一致的商业字体。
- 不强制把照片、复杂插画、烟雾、玻璃、粒子和 3D 主视觉矢量化。
- 不在第一阶段实现 PowerPoint 插件、宏或云端协作编辑器。
- 不把结构化 JSON 变成人工维护的第二内容源；`slides_plan.md` 继续是内容事实来源。

## 4. 核心设计决策

### 4.1 完整视觉稿优先

gpt-image-2 先生成包含全部文字、数字、图形和视觉素材的完整幻灯片。该图片称为 `visual_master`，是后续重建和视觉比较的唯一母版。

### 4.2 反向分层，而不是预先留空

系统从 `visual_master` 中检测文字和视觉对象，局部清除旧文字、提取复杂素材，并用 PowerPoint 原生对象重建。clean plate 是生成后的中间产物，不是 gpt-image-2 的初始输入。

### 4.3 已知文案优先于 OCR

只要存在 `slides_plan.md`、`slides_plan.json`、`slide_spec` 或生成 prompt，原生文本内容必须来自这些确定来源。OCR 和视觉模型用于：

- 识别文字框位置、旋转角度和层级；
- 判断换行和段落结构；
- 检测颜色、字号、字重、对齐和字距；
- 将视觉母版中的文字区域与源文案元素匹配。

只有摄取无源稿的外部图片或图片型 PPTX 时，OCR 才承担文字识别任务。

### 4.4 原始像素优先于重新生成

复杂视觉对象默认直接从母版提取原始像素。AI 生成只用于补全不可见区域或处理无法合格分离的素材，避免身份、构图、材质和光源漂移。

## 5. 总体架构

```text
slides_plan.md + style/layout + 用户素材
                    │
                    ▼
       gpt-image-2 完整视觉母版
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
  语义文字恢复             视觉对象分层
  源文案匹配               A1 原像素直抠
  文字区域 mask            A2 遮挡局部补全
  局部背景修复             B  AI 分离重建
        │                       │
        └───────────┬───────────┘
                    ▼
          EditableScene 派生场景图
                    │
                    ▼
      原生文本 + 原生形状 + 独立图片
                    │
                    ▼
                PPTX 渲染
                    │
                    ▼
      Office 真渲染 + 母版差异分析
                    │
              不合格则局部迭代
```

## 6. EditableScene 数据模型

`EditableScene` 是派生数据，由视觉母版、源文案和分析结果生成，不人工修改。每页包含：

```json
{
  "slide_number": 3,
  "visual_master": "images/slide-03.png",
  "clean_plate": "editable/slide-03/clean-plate.png",
  "canvas": {"width": 1536, "height": 864},
  "elements": [
    {
      "id": "title",
      "type": "native_text",
      "source_text_id": "slide-3-title",
      "content": "市场痛点",
      "bbox_px": [116, 73, 690, 96],
      "rotation": 0,
      "z_index": 30,
      "style": {
        "font_candidates": ["Noto Sans CJK SC", "Microsoft YaHei", "PingFang SC"],
        "font_size_pt": 37,
        "font_weight": 700,
        "color": "#17211B",
        "align": "left",
        "line_spacing": 1.0,
        "char_spacing_pt": 0
      }
    },
    {
      "id": "hero_object_1",
      "type": "image_layer",
      "bbox_px": [845, 132, 552, 612],
      "z_index": 18,
      "layer_strategy": "direct_extract",
      "asset": "editable/slide-03/assets/hero-object-1.png",
      "mask": "editable/slide-03/masks/hero-object-1.png",
      "occlusion_completed": false
    }
  ]
}
```

每个元素必须记录来源、生成策略和质量结果，避免用户无法判断某个对象是原像素、AI 补全还是 AI 重建。

## 7. 文字原生化流程

### 7.1 文字检测与源文案匹配

1. 从 plan、prompt 和 slide spec 构建本页确定文案集合。
2. 使用 OCR 获得文字行或文字块的多边形区域。
3. 使用视觉模型补充 OCR 容易遗漏的旋转文字、浅色文字、艺术字和小标签。
4. 通过字符串相似度、阅读顺序、元素角色和空间关系，把检测区域匹配到确定文案。
5. 对 AI 生成的乱码或源稿中不存在的装饰文字标记为 `unmatched_generated_text`，默认擦除，不作为业务内容保留。

### 7.2 文字 mask

文字 mask 不能只使用外接矩形。系统应结合：

- OCR/视觉多边形；
- 局部前景色和背景色差；
- 抗锯齿像素扩张；
- 阴影、描边和发光范围；
- 邻近图形边缘保护。

mask 应略覆盖文字阴影和发光，但不能吞掉卡片边框、图标和人物轮廓。

### 7.3 背景修复路由

- 纯色、简单渐变、规则纹理：传统图像修复或 LaMa 类本地修复。
- 照片、复杂纹理、插画和光效：gpt-image-2 masked edit。
- 无论使用何种修复引擎，只允许把 mask 范围及受控羽化边缘合成回母版，mask 外像素保持原样。
- 每个文本区域单独保留 before、mask、repair 和 composite 证据图。

### 7.4 原生文本样式恢复

系统从视觉母版估计字号、字重、颜色、对齐、行距和字距，并从预设中文字体库中检索最接近的真实字体。字体选择优先级为：

1. 用户或模板明确指定字体；
2. 当前系统已安装且跨平台可用的字体；
3. Noto Sans/Serif CJK 系列；
4. Windows、macOS 的平台 fallback。

不允许为了像素一致而把业务文字转换为不可编辑字形图片。字体无法完全匹配时，优先保证可读性、层级、行宽和换行结构。

## 8. 重叠视觉素材分层

### 8.1 A1：原像素直接抠取，默认策略

适用条件：

- 对象轮廓能够稳定识别；
- 前景与背景或相邻对象可分离；
- 半透明和细边缘质量可接受；
- 用户主要需要选择、隐藏、缩放、替换或小范围移动对象。

处理流程：

1. 检测对象实例和遮挡顺序。
2. 使用实例分割获得初始 mask。
3. 使用 alpha matting 精修毛发、玻璃、阴影和抗锯齿边缘。
4. 直接从 `visual_master` 读取原像素，生成透明 PNG。
5. 对对象移除后的背景区域局部修复。
6. 按原坐标和 z-order 重组。
7. 在黑、白和彩色测试底上检查光晕和背景污染。

A1 得到的是对象当前可见区域。它可以实现原位像素保真，但被遮挡部分在源图中不存在。

### 8.2 A2：原像素保留 + 被遮挡区域局部补全

当对象容易分割但遮挡区域会影响移动时，进入 A2：

1. 所有可见区域继续使用母版原像素。
2. 推断被遮挡区域的轮廓。
3. 只让 AI 补全不可见部分。
4. 将原像素覆盖在 AI 补全结果上，确保可见区域不发生变化。
5. 检查补全对象独立显示和重新叠加后的连续性。

A2 属于保真修复模式，不允许改变对象风格、身份、角度和材质。

### 8.3 B：AI 分离重建

仅在以下条件触发：

- A1 的边缘、半透明或背景污染质量不合格；
- A2 无法合理恢复被遮挡区域；
- 多个对象纹理高度粘连，无法稳定分割；
- 对象包含烟雾、粒子、复杂玻璃折射或大面积毛发；
- 原位重组无法通过视觉差异门；
- 用户明确选择设计模式。

处理流程：

1. 每个对象单独生成，不要求模型一次输出全部分层素材。
2. 把完整母版、目标对象区域和遮挡关系作为参考。
3. prompt 明确约束造型、透视、材质、光线方向、颜色和相对尺寸。
4. 输出单对象素材后进行抠图或透明背景处理。
5. 按原始 z-order 重新组合。
6. 某个对象身份漂移时只重做该对象，不重生成整页。

### 8.4 自动策略选择

策略选择由质量证据驱动：

- 分割置信度；
- mask 边缘完整性；
- 前景中的背景污染；
- 半透明区域质量；
- 遮挡面积和不可见部分的重要性；
- 黑、白、彩色底测试结果；
- 原位重组与母版的非文字区域差异；
- 对象移动后是否暴露缺失区域。

执行顺序固定为 A1 → A2 → B。用户选择设计模式时可以直接进入 B。

## 9. 图表、Logo 和特殊对象

### 9.1 图表

- 如果有源数据，图表主体优先重建为原生 PowerPoint chart。
- 如果没有源数据，图表主体可以作为独立图片，但所有可识别的标题、图例、坐标轴、数据标签、来源和注释必须转换为原生文本。
- 密集科研图表可以按逻辑面板拆成多个独立图片，不强行逐元素矢量化。

### 9.2 Logo

- 用户提供原始 Logo 时，始终使用用户原图或 SVG，不使用 AI 重绘。
- 视觉母版里出现但用户未提供源文件的 Logo，可抠为独立图片，并提示用户核对品牌准确性。
- AI 生成的伪 Logo 不得被标记为真实品牌素材。

### 9.3 简单形状

矩形、圆角卡片、圆、线条、箭头和简单分隔符在轮廓、颜色和阴影能够稳定估计时，可以转换为原生 shape。复杂装饰优先保持图片层，避免过度碎片化导致 PowerPoint 难以编辑。

## 10. gpt-image-2 Provider

### 10.1 SDK

新增基于 OpenAI Python SDK 的 provider，使用统一接口：

```python
provider.generate(prompt, size, quality)
provider.edit(image, mask, prompt, size, quality)
```

配置从环境变量读取：

```dotenv
OPENAI_BASE_URL=https://api.krill-ai.com/v1
GPT_IMAGE_MODEL_NAME=gpt-image-2
GPT_IMAGE_QUALITY=high
```

`OPENAI_API_KEY` 由开发者在本机 `.env` 中另行设置，不在文档中保存示例密钥。仓库根目录 `.env` 仅作为本仓库本地开发 fallback。该文件已被 `.gitignore` 排除，不得提交、复制到输出目录或写入日志。部署、CI 和作为外部 skill 调用时仍优先使用平台环境变量或 Secret 管理。

### 10.2 URL 规范化

SDK 直接接收包含 `/v1` 的 `base_url`。现有手写 HTTP 实现会自行拼接 `/v1/images/generations`，新 provider 不复用该拼接逻辑，避免形成 `/v1/v1/...`。

### 10.3 能力探测

第一次使用该渠道前必须运行冒烟矩阵：

1. `images.generate` 是否返回 `b64_json`。
2. 支持的横版尺寸和质量参数。
3. `images.edit` 的 `image`、`image[]` 和 mask multipart 兼容性。
4. mask 透明度语义。
5. mask 外区域是否会漂移。
6. 是否支持多参考图。
7. PNG 是否保留 alpha。
8. 中文完整页、文字擦除和遮挡补全各生成一例。

探测结果写入 provider capability cache，后续根据实际支持能力路由，不硬编码未经验证的假设。

## 11. PPTX 渲染

Python 继续负责会话、素材、mask、模型调用和流程编排。原生 PPTX 对象渲染可分阶段实现：

1. 第一阶段复用 `python-pptx`，支持原生文本和独立图片层。
2. 当需要更丰富的原生 chart、table、SVG 和母版能力时，引入 PptxGenJS 渲染 sidecar。
3. 两种渲染器都读取同一份 `EditableScene`，不让业务逻辑依赖具体库。

PPTX 中的层级顺序必须严格使用 `z_index`，背景 clean plate 位于最底层，独立视觉素材按遮挡关系叠加，原生文本位于对应视觉层级。

## 13. 质量门

### 13.1 语义质量

- plan 中所有业务文字均能在 PPTX 中找到对应原生文本对象。
- 不允许丢字、重复文字、错误数字或错误单位。
- 无源稿 OCR 结果必须标记置信度，低置信度内容进入人工检查列表。

### 13.2 视觉质量

- 母版中的旧文字不可在 clean plate 中形成明显残影。
- 原生文字不应溢出、遮挡或产生意外换行。
- A1/A2 素材在黑、白、彩色底上不得出现明显光晕。
- 原位重组后的非文字区域应与母版保持高度一致。
- B 路径生成的对象不得出现身份、数量、方向或光源明显变化。

### 13.3 结构质量

- 每页至少包含原生文本对象，不能退化为单张整页图片。
- 所有独立素材都应有可选择的 picture object 和明确对象名称。
- PPTX XML、关系文件和媒体引用必须通过结构验证。

### 13.4 渲染质量

- 至少使用一个真实 Office 渲染后端渲染所有页面。
- 发布前在 PowerPoint、Keynote、LibreOffice 中至少抽查两种。
- 字体缺失、字距漂移、图表重排和对象错位均视为失败，不以 XML 验证通过替代视觉检查。

## 14. 错误处理与回退

- 文字区域无法可靠匹配源文案时，页面暂停原生化并输出人工检查报告，不猜测业务文字。
- 局部修复失败时只重试该文字块或对象，不重新生成整页。
- A1 失败进入 A2，A2 失败进入 B；B 失败时保留未分层视觉对象并在报告中说明。
- Provider 不支持编辑接口时，允许使用本地 inpainting 完成简单文字擦除，但不得伪装成已完成复杂遮挡补全。
- PPTX 渲染失败时保留场景图和素材，允许更换渲染器后重建，不重新调用图片模型。

## 15. 安全

- API Key 只从进程环境、平台 Secret、显式私有 env 文件或本仓库被忽略的 `.env` 读取。
- 不在 prompt、日志、metadata、quality report、测试快照或异常正文中记录 API Key。
- 日志只显示 endpoint host，不显示 Authorization header。
- 已经出现在聊天、Issue、日志或提交中的密钥视为泄露，必须更换。
- `.env`、生成素材和可能包含敏感内容的 trace 默认不进入 Git。

## 16. 测试策略

### 16.1 单元测试

- 源文案与检测框匹配。
- base URL 规范化和 provider 响应解析。
- mask 膨胀、羽化和邻近边缘保护。
- A1/A2/B 路由条件。
- bbox 像素到 PowerPoint 坐标转换。
- z-order 和对象命名。

### 16.2 集成测试

- 纯色背景文字页。
- 渐变背景数据页。
- 文字覆盖照片页。
- 多个重叠插画对象页。
- 半透明玻璃或阴影页。
- 图表主体图片加原生标签页。
- 中文、英文和中英混排页。

### 16.3 Provider 冒烟测试

真实 API 测试使用显式 marker，默认测试套件不调用收费接口。测试只输出脱敏后的状态、尺寸、响应类型和耗时。

### 16.4 回归测试

固定视觉母版和源文案，比较：

- 原生文本完整性；
- clean plate 文字残影；
- 原位重组视觉差异；
- Office 渲染结果；
- PPTX 原生对象数量和类型。

## 17. 分阶段交付

### 阶段一：文字原生化 MVP

- 完整视觉母版保持不变。
- 已知文案匹配、文字 mask、局部擦除和原生文本框。
- 复杂视觉暂时保留在 clean plate。
- 输出 editable 和 visual-master 两份 PPTX。

### 阶段二：原像素视觉分层

- A1 实例分割和 alpha matting。
- 重叠层级推断。
- 独立图片对象、背景修复和原位重组质量门。

### 阶段三：遮挡补全与设计模式

- A2 被遮挡区域局部补全。
- B AI 分离重建。
- Provider 能力探测和素材级重试。

### 阶段四：结构增强和自动闭环

- 简单 shape、表格和图表原生化。
- 字体候选检索。
- Office 渲染差异分析和自动微调。
- PptxGenJS sidecar。

## 18. 验收标准

可编辑分层功能完成阶段三、进入正式发布时必须满足：

1. `slides_plan.md` 中的标题、正文、数字和标签全部是 PowerPoint 原生文本。
2. 用户修改任一文本后，背景不露出旧文字。
3. 完整视觉母版仍由 gpt-image-2 生成，初始构图和视觉语言不因可编辑模式被预先简化。
4. 重叠素材默认使用 A1，失败时按 A2、B 顺序自动降级，并记录原因。
5. 每页保留 scene、mask、素材来源和质量报告。
6. editable PPTX 不是单图幻灯片，且通过真实 Office 渲染检查。
7. 原有整页图片模式继续工作，用户可以随时回退到 visual-master 版本。

## 19. 主要风险

- AI 生成字形不对应真实字体，原生文字可能存在细微视觉差异。
- 复杂背景上的文字擦除可能损伤纹理或人物边缘。
- 大面积遮挡无法仅靠原图恢复，A2/B 可能发生风格或身份漂移。
- 中文字体在 PowerPoint、Keynote 和 LibreOffice 中的替换策略不同。
- 过度分层会产生大量难以管理的小对象，因此默认只拆语义文字和有实际编辑价值的视觉对象。

这些风险通过 visual-master 双交付、素材级 provenance、A1/A2/B 路由和真实 Office 渲染闭环控制，而不是通过降低 gpt-image-2 的完整页面设计能力规避。
